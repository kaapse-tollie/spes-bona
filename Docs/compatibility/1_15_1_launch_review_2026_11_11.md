## Panama: native data control

Neither SB nor CMF defines `STATE_PANAMA`. Native
`map_data/state_regions/06_central_america.txt` assigns state ID `343`, port
`xD0EF40` and city `x8A8A20`.

| Record | SB and native 1.15.1 coordinates |
| --- | --- |
| Land-port anchor `34303` | `(2276.011474609375, 1723.7967529296875)` |
| Naval anchor `8422908` | `(2275.167724609375, 1724.5478515625)` |
| Port locator `343` | `(2275.747314, 1724.006714)` |

Both anchor records are byte-identical to native. The existing native-route
comparison also passes: both anchors and an entire direct sea route are intact.
Sampling the land anchor and locator using the repository validator's coordinate
conversion gives pixel `(2276, 1891)` in each 8192 × 3616 province raster.
Both native and SB rasters return `x8A8A20`, matching the logged mismatch with
the declared port `xD0EF40`.

This establishes a native source inconsistency, not an SB geometry regression.
SB's raster, spline and port-locator files were also unchanged by the patch.
No Vanilla-only launch was performed, and the effect on Panama's actual port
operation is not established by this log. Preserve the observation without
moving native hubs or rerouting splines speculatively.
