## Cape and Caledon previews — PLAY115-03

**Cape:** DP wants the triggered event and its possible effects visible for each
completion route, rather than only “The Spirit of the Cape Settled”. The
[Cape JE](../../common/journal_entries/1-01_sb_cape_politics.txt) hides its event
dispatch inside the effect. Its `event_outcome_desc` selects a single
`first_valid` branch from current conditions, rather than exposing each possible
route independently. Improve the native outcome/event preview while preserving
priority between overlapping routes, event timing and effect ownership. Preview
must never execute the reward or duplicate event dispatch.

**Caledon:** DP wants the normal Vanilla DLC presentation where there is no
alternative event choice. The [frontier JE](../../common/journal_entries/1-07_sb_bst_frontier.txt)
puts an unconditional `event_outcome_desc` on the Oranje outcome. Both linked
[frontier events](../../events/sb_bst_frontier_events.txt), `.300` and `.310`, have
one option. Review a matching native single-reward example before implementing;
preserve the delayed recipient, settlement guards and actual rewards. The two
different JE victory routes are still distinct; the note concerns the effects
display within a route, not removing one of those victories.

## Prerogative preview hover — PLAY115-04

The reported error is a real missing-data-context failure:
`sb_prerogative_country_title` requires `JournalEntry.GetCountry`, but the hover
supplies no `JournalEntry` object. The [JE title](../../localization/english/sb_l_english.yml)
selects this [country-dependent key](../../localization/english/sb_institutions_l_english.yml)
whenever `IsInGame` is true. That distinguishes the lobby from a campaign; it
does not establish an instance context in every in-game preview.

The [native tooltip GUI](</Users/depro/Library/Application Support/Steam/steamapps/common/Victoria 3/game/gui/custom_tooltip.gui>) has a `FancyTooltip_JournalEntryType` reader using
`JournalEntryType.GetName`, demonstrating a type-only title consumer. The exact
hover path still needs visual replay. The existing
[title fixture](../../tests/test_zulu_institutions_core.py) tests the lobby and
live instances but always supplies an instance when in game, missing the
reported case.

The correction must give type-only previews a safe title while retaining
country-specific royal/chiefly naming where the actual JE owner is available.
Do not substitute the player's country for the displayed owner. Cover lobby,
in-game preview without an instance, full journal, both constitutions and a
foreign country after tag switching. No title wording or GUI was changed here.

## Journal groups — EXT115-11

Grouping already exists through native categories: 18 `je_sb_*` definitions use
Historical Content, four use Global International Situations and two use
Expeditions. SB currently defines no custom journal groups. This count concerns
source definitions, not entries active in a particular campaign.

SB-specific thematic grouping is queued for the JE extension pass. Keep
country-context entries separate from contextless shared situations; inspect
which groups are useful for each country, visibility, ordering and illustrations.
Changing the group must not change activation or participation. CMF supplies
visibility controls, but group membership alone is not a CMF feature.

## Natal objective timers — PLAY115-05

DP clarified that **Secure Natal / Defend Natal should enforce after holding the
objective**, rather than giving their settlement a fixed duration.

Both [custom war goals](../../common/war_goal_types/sb_story_war_goals.txt) set
`assent_required` and have no `mirrored_wargoal`. The native 1.15
[war-goal schema](</Users/depro/Library/Application Support/Steam/steamapps/common/Victoria 3/game/common/war_goal_types/war_goal_types.md>) states that the former excludes timer
enforcement and that a mirror contract is also required to enable it. Removing
the exclusion alone is insufficient. Native defaults are five progress points
per week gained/lost, but timer rate and mirror behaviour remain implementation
choices to review rather than an authorised custom balance value.

The [story enforcement helper](../../common/scripted_effects/sb_story_war_effects.txt)
and [timer/final-peace handlers](../../common/on_actions/sb_diplomatic_play_on_action_handlers.txt)
currently distinguish timer evidence from accepted final demands. Review that
contract alongside the goals. Test both sides, interrupted control, any mirror,
continued war, subsequent peace and save/reload; settlement effects must occur
once at the intended phase. No live war or script was altered.

## Natalia on the Swazi defending side — PLAY115-06

DP requests that Natalia cannot join SWZ's defending side against ZUL in the
scripted campaign. The [frontier event](../../events/sb_swazi_frontier_events.txt)
opens native `dp_conquer_state`; the start callback records its exact identity in
`sb_zulu_swazi_play_scope`. SB has no current override of the native
[`can_join_side_in_diplomatic_play` rule](</Users/depro/Library/Application Support/Steam/steamapps/common/Victoria 3/game/common/scripted_rules/00_scripted_rules.txt>).

Implement the restriction at the relevant joining/eligibility boundary, confined
to this marked play and defending side. Preserve native eligibility and unrelated
Natalia diplomacy. Test player and AI/swayed joining, unrelated ZUL/SWZ conflicts,
and ordinary Natalia wars; inspect automatic participation where applicable.
